# UAV 통신 연구 대시보드

군집 UAV 비행 기록에서 수색망의 연결 상태, 단절 시점, 중계 드론의 이동, 재연결 과정을 살펴보는 NiceGUI 대시보드입니다. `FINAL-V`는 대시보드 코드를 팀 시뮬레이터에서 분리한 첫 기준점입니다.

## Windows에서 열기

Python 3.12를 설치한 뒤 저장소 폴더에서 한 번 실행합니다.

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r nicegui_dashboard/requirements.txt
```

팀에서 받은 재생 자료는 아래 이름으로 둡니다. GitHub에서는 대시보드 코드와 검증 도구를 배포하며, 전체 비행 녹화본은 별도로 전달합니다.

| 로컬 위치 | 표시되는 자료 |
| --- | --- |
| `data/UAV_대시보드_v2.html` | 전체 70개 지역의 기본 대형·재배치 적용 비행 140건 |
| `data/상암DMC_대시보드.html` | 상암 최신 공유본의 두 비행과 사건 상세 |
| `data/results/` | 완료된 실험이 등록되는 로컬 보관소. 처음 실행할 때 빈 보관소로 시작할 수 있습니다. |

`Start-Dashboard.cmd`를 실행하고 브라우저에서 [전체 지역](http://127.0.0.1:8092/regions)을 엽니다. 창에서 `Ctrl+C`를 누르면 종료됩니다. 8092에서 기존 대시보드를 쓰고 있다면 `.\Start-Dashboard.cmd --port 8196`을 실행하고 [8196 전체 지역](http://127.0.0.1:8196/regions)을 엽니다. 자료가 다른 위치에 있으면 `settings.example.json`을 `settings.local.json`으로 복사해 경로를 지정합니다. 같은 이름의 환경 변수가 있으면 그 값을 우선합니다.

## 기록을 보는 순서

현재 전체 지역 화면은 `nicegui_dashboard/data/region_selection.json`의 **시연용 50개 지역**을 표시합니다. 원본 70개 가운데 미완료 비행, 단절 개선이 악화되거나 미미한 사례, 측정된 선행탐지 성능이 낮은 사례를 검토하여 20개를 표시 대상에서 제외했으며, 선정 기준과 지역별 근거는 같은 파일에 보존합니다. 카드·검색·필터·전체 실행·실패 재시도는 이 50개 범위를 사용합니다. 이는 발표 자료 선택이며 연구 평가 정의나 원본 결과를 변경하지 않습니다. **선정된 50개의 성능을 원본 70개 전체의 대표 통계로 해석하면 안 됩니다.** 제외 지역의 기존 기록과 원본 70지역 공유본은 보관합니다.

1. **전체 지역**에서 지역과 비행 방식을 고르고 비행을 재생합니다. 상암 DMC는 지역 목록에서 선택할 수 있습니다. 상암 재배치 적용 기록의 사건 13은 2,845.5초에 시작해 2,889초에 끝납니다.
2. **사건 상세**에서 시각을 옮기며 기체 위치·링크·통신 여유·단절과 재연결을 같은 시각에 비교합니다. 각 공유본은 자료 식별값과 변환본을 확인해 읽습니다.
3. **로컬 결과**는 이 컴퓨터에 등록된 완료 기록을 보여 줍니다. 팀에서 같은 형식으로 내보낸 결과 폴더가 있으면 아래 명령으로 등록합니다. 경로를 실제 결과 폴더로 바꿔 실행하세요.

```powershell
.\.venv\Scripts\python.exe -m nicegui_dashboard.ingest publish "D:\flight-exports\run\revision" --output-root .\data\results
```

기본 결과 서비스는 약 10초마다 보관소를 확인합니다. 같은 실행·변환본을 다시 등록해도 목록에는 한 건으로 남습니다. 내보낸 결과 등록과 새 비행 계산은 별도 작업입니다.

## 팀 시뮬레이터가 바뀌면

1. **전체 지역 → 팀 코드 갱신**을 누릅니다. 버튼 옆에서 연결된 팀 버전을 확인합니다.
2. **실행 범위**에서 한 곳을 시험하려면 지역 카드와 **선택 지역**을 고릅니다. 한 번에 돌리려면 **전체 50개 지역**을 고릅니다. 화면에 해당 팀 버전과 설치된 지도 자료로 실행 가능한 지역 수가 표시됩니다.
3. **새 비행 실행**을 누릅니다. 선택한 팀 버전으로 재배치 적용과 기본 대형 비행을 계산하고, 같은 지역의 별도 기준 비행에서 예측 성능을 평가합니다. 전체 실행에서는 가능한 지역을 순서대로 처리합니다. **실행 관리**를 펼치면 지역별 진행 상황과 실패·제외 이유를 확인할 수 있습니다.
4. 완료된 지역 카드를 열면 평소 쓰던 네 개의 지표 카드, 2D·3D 지도, **단절·복구 과정 보기**에 새 비행의 기록이 표시됩니다. **실험 비교**에는 같은 팀 버전·지도·시드로 계산한 기본 대형과 모델 적용 비행의 9개 항목이 표시됩니다. **현재 모델**에서는 해당 비행의 판단 주기, 사용한 모델과 그 모델로 평가한 성능을 확인할 수 있습니다.

**표시할 비행 기록**을 바꾸면 카드·필터·비교표·모델 정보도 해당 기록을 기준으로 바뀝니다. 지도에서 **기본 대형**을 선택하면 같은 팀 버전·지역·시드의 기본 비행이 재생됩니다. 비교 수치만 있고 기본 대형 재생 기록이 빠진 경우에는 같은 버전의 새 비행 실행으로 기본 대형 기록을 보완할 수 있습니다. 사용자가 시각이나 사건을 직접 선택한 동안에는 새 결과가 도착해도 분석 중인 기록을 유지합니다.

첫 실행은 대시보드 폴더 옆의 `team-simulator`에 팀 코드를 내려받습니다. 다음부터는 같은 폴더를 팀 저장소의 `main`과 맞춥니다. 로컬에서 파일을 바꾸거나 별도로 커밋한 경우에는 중단하고 이유를 표시합니다.

실행을 시작할 때 선택한 팀 커밋이 해당 묶음의 끝까지 적용됩니다. 같은 버전으로 이미 성공한 지역은 저장된 비행을 재사용합니다. 실패한 지역은 이전 완료 기록을 계속 열 수 있고, **실패 지역만 재시도**는 현재 표시하는 50개 중 실패한 지역만 원래 팀 버전으로 실행합니다. 연결 버전이 바뀌었다면 재시도를 막으므로 현재 버전의 새 실행을 선택합니다. 실행 요청 후 브라우저를 닫아도 컴퓨터에서 작업은 계속됩니다.

진행 중인 갱신을 중단하면 해당 묶음의 대기 작업과 현재 계산을 종료하고 이미 완료된 비행은 보존합니다. 중단 처리가 끝난 뒤 다른 팀 버전으로 새 실행을 요청할 수 있습니다.

## 지표를 읽을 때

- 메인 카드의 **수색망 단절 횟수**는 비행 중 새로 시작해 1초 이상 지속된 단절을 셉니다. 사건 타임라인의 수색망 단절 목록에는 1초 미만 구간과 시작 시점부터의 단절도 들어 있어 목록 수가 다를 수 있습니다.
- **선행탐지율**은 선택한 지역·팀 버전·모델의 별도 평가용 기준 비행에서 계산합니다. 현재 재생 비행이나 기본 대형 탭의 단절 건수를 분모로 쓰는 값이 아닙니다.
- 수신 신호, 실제 통신 그룹, 통신 여유·병목 경로, 모델 예측은 각 기록의 시각과 관측 유효성에 따라 표시합니다. 기록이 없는 이전 비행에 다른 버전의 수치를 가져와 채우지 않습니다.
- 로컬 결과의 **다중 비교**는 실험 조건과 지표 정의를 구분하고, 같은 그룹에서 값이 빠진 비행은 결측으로 집계합니다. 선택·유효·결측 건수와 실행별 제외 이유를 확인할 수 있습니다.
- 비행 기록의 검증·등록 완료는 연구 임무 성공과 다릅니다. 연결 유지율과 PDR뿐 아니라 임무 완료 여부와 실제 경로도 함께 확인해야 합니다.

분당에서 검증한 팀 버전 `5a6a775` 기준으로, 실행 자료의 로컬 복사본은 버전당 약 2.4 GiB이며 같은 버전의 지역들이 함께 사용합니다. 분당의 새 비행 기록은 약 37 MiB였습니다. 다른 지역의 비행 길이와 관측 수에 따라 기록 크기는 달라집니다. 결과 보관소의 용량 한도는 `settings.local.json`의 숫자 항목 `UAV_MAX_OUTPUT_GIB` 또는 실행 옵션 `--max-output-gib`로 지정합니다.

최초 한 번은 팀 배포본의 실행 자료를 연결해야 합니다. `settings.local.json`의 `UAV_RESEARCH_CORE`에 `code`와 `dashboard_execution/selected_maps.json`이 들어 있는 연구 자료 폴더를 지정합니다. 그 상위 폴더의 `runtime_environment.json`에 연구용 Python 경로가 있으면 그대로 사용합니다. 별도 지정이 필요하면 `UAV_RESEARCH_PYTHON`에 실행 파일 경로를 입력합니다. 이 컴퓨터의 설정과 대용량 자료는 GitHub에 포함되지 않습니다.

기존 70개 지역의 기본 대형·적용 기록은 당시 조건의 비교용입니다. 새로 실행할 때는 같은 팀 모델과 재배치 정책으로 각 지역의 비행을 계산합니다. 팀 실험 목록이 직접 지원하는 지도는 팀의 기본 실행 경로를 사용합니다. 목록에 없거나 기존 평가용으로 보존된 지도는 대시보드에 등록해 둔 원본 지도의 SHA-256을 확인한 뒤 **시연용 입력**으로 실행합니다. 이때 결과에는 시연용이라는 구분과 지도의 원래 연구 용도를 함께 기록합니다. 지도 파일이 다르거나 팀이 입력 방식을 바꿔 호환성을 확인할 수 없으면 지역별 진행 상황에 이유가 표시됩니다. ## 지역별 역할·고도 보조 표시

계획 배치 제어기(`halfsec_planned_eight`)의 적용 비행에는 전체 통신·단절 예측 패널 아래 **배치와 비행 운용** 패널이 있습니다. 70개 지역 모두 같은 표시를 사용하되, 고정 중계·고도 조정 중계의 기체와 채택 여부는 해당 비행의 실제 배치 기록에서 읽습니다. 고정 중계와 고도 조정 중계는 같은 진한 파랑으로 표시하고, 일반 중계는 기존 보라색입니다. 노랑·빨강의 통신 상태 표시가 역할색보다 우선하며 기존 기체 이름과 네 메인 지표는 유지합니다. 역할 버튼으로 기체를 선택하고, **고도와 통신 여유 함께 보기** 또는 **고도 운용 기록**을 펼쳐 시각별 기록을 확인합니다. 운용 기록의 시각을 누르면 지도와 통신 표시가 함께 이동합니다. 해당 지도에서 채택하지 않은 고정·고도 역할이나 발생하지 않은 이동을 임의로 만들어 표시하지 않습니다.

분당 `e7f4517`의 검증 예시에서는 R4가 고정 중계, R2가 고도 조정 중계입니다. R2의 56초 상승, 79초 고도 조정 전 이동 대기, 87초 하강 후 확인, 94초 이전 높이 복원을 볼 수 있습니다. 314.5초에는 80m에서 통신 확인을 기다리고 316.5초에는 해당 구간을 통과합니다. 1370초의 경로 정체 해소는 수색 완료가 아니라 안전한 우회·통로 확보입니다. 1699.5초 경로 완료와 1729.5초 임무 종료도 구분합니다. 이 기체와 시각은 다른 지역에 그대로 적용하지 않습니다.

새 비행 계산에서는 원래 항법 콜백의 호출 횟수와 반환값을 유지하면서 운용 기록을 자동 수집하고, 결과 묶음의 `operations.json`에 저장합니다. 이 파일은 결과의 검사값과 비행·변환본·팀 코드·지도·모델에 연결됩니다. 기존 비행을 보강할 때에는 원본 결과를 바꾸지 않고 동일 조건으로 관측한 뒤 위치·통신·판단·사건·지표를 전수 대조하며, 통과한 기록만 `UAV_DATA_ROOT/flight_operations/<run_id>/<revision>.json`에 별도로 저장합니다. 기본 대형에는 새 패널을 표시하지 않습니다. 새 기록이 없거나 해당 제어기 형식이 바뀌었으면 그 상태를 표시하고 다른 비행의 기록을 가져오지 않습니다.

기존 완료 비행에 누락된 보조 기록을 만들 때는 **연구용 Python 환경**에서 다음 모듈을 사용합니다. 이 명령은 적용 비행을 한 번 다시 관측하고 제어 집계도 함께 보존합니다. 단순 재생이나 새 비행의 자동 수집에는 실행할 필요가 없습니다. `--retain`은 선택 사항이며, 보존한 기록은 `--reuse-observation <관측_임시폴더>`로 재계산 없이 다시 검증·연결할 수 있습니다.

```powershell
python -B -m nicegui_dashboard.team_operations_capture --output-root <결과_보관소> --pin <실행_ID> <변환본_ID> --retain <관측_임시폴더>
```

## 현재 모델의 지역 평가 8개 지표

각 지역의 **현재 모델** 탭은 선택한 적용 비행의 제어 4개 지표와 동일 지도·조건에서 별도로 수행한 기준 비행의 예측 평가 4개 지표를 구분하여 표시합니다. 연구 보고서의 여러 지도 종합 평가로 표시하거나 다른 모델의 수치를 가져오지 않습니다. 기본 대형을 보고 있을 때에는 짝지어진 적용 모델의 평가라는 안내를 표시합니다.

- 제어: 시간당 새 지속 단절, 시간당 지속 단절 시간, 0.25초 내 전달률, 평균 중계기 이동 거리. 실행에 고정된 팀 코드의 `fast_halfsec.evaluation.pooled([row])`를 그대로 호출합니다. 이동 거리는 원본 0.1초 운동 계산에서 누적한 중계기 5대의 **수평 이동거리 합계**를 비행별로 평균한 값이며, 이 화면은 적용 비행 1회 기준입니다. 고도 이동이나 0.5초 재생 위치의 근사 거리를 더하지 않습니다.
- 예측: 선행 탐지율, 경보 정밀도, 오경보·늦은 경보, AP. 기존 기준 비행과 `final_v1.halfsec_joint.run.forecast_cases`를 유지하고 공식 `evaluate(..., with_ap=True)`를 호출합니다. 유효한 평가 시점이 없으면 AP를 임의로 0으로 채우지 않고 미산출로 남깁니다.
- 다음 새 비행 계산부터 운용 단계, 제어 집계와 AP가 함께 자동 저장됩니다. 기존 완료 결과를 재사용하는 것은 새 계산이 아니며, 누락 기록이 있는 이전 결과의 보강에는 별도 검증이 필요합니다. 모든 지역에서 해당 비행의 검증된 자료만 표시합니다.

기존 비행의 AP 보강은 연구용 Python에서 `nicegui_dashboard.team_evaluation_recovery --with-ap`로 별도 평가 비행만 다시 계산하고, 기존 사건·경보·점수열·집계가 같은지 검사한 뒤 `flight_evaluations/<run>/<revision>.json`에 보존합니다. 이미 AP가 기록되어 있으면 재계산하지 않습니다. 제어 집계는 검증된 원본 관측과 기존 재생의 모든 채널을 대조한 뒤 `flight_model_metrics/<run>/<revision>.json`에 보존합니다. 원래 적용·기본 대형 결과 묶음을 수정하지 않습니다.

검증된 `e7f4517`·30회차의 기존 평가에는 `--reuse-sealed-scores` 옵션으로 봉인된 비교 예측 점수를 재사용할 수 있습니다. 같은 모델·지도·조건과 연구 소스 검사값을 확인하고, 기준 비행의 행동과 공식 정답·AP 계산은 유지하며 기록용 비교 추론만 생략합니다. 전체 계산과 연결 상태·정답·점수·사건·경보·집계가 정확히 일치하는 것을 검증했습니다. 새 비행의 자동 평가는 원래 계산 경로를 사용합니다.

## 코드와 확인 방법

| 폴더 | 역할 |
| --- | --- |
| `nicegui_dashboard/` | 화면 진입점, 지도·사건 재생, 비교, 보관소 연동 |
| `nicegui_dashboard/vendor/` | 기준 공유본을 읽고 재생하는 데 쓰는 고정된 화면 자원과 보조 데이터 |
| `result_service/` | 결과 형식 검사, 등록, 조회, 내보내기 |
| `nicegui_dashboard/tests/` | 자료 읽기, 등록, 비교, 상태 동기화와 실제 브라우저 화면 확인 |

위의 두 재생 자료를 준비한 뒤 다음 명령으로 테스트합니다.

```powershell
.\.venv\Scripts\python.exe -B -m unittest discover -s nicegui_dashboard/tests -v
```

브라우저 검증에는 Node.js와 Chrome이 필요합니다. 대시보드를 실행한 상태에서 아래 명령을 사용합니다. 이 검증은 전체 지역 목록, 로컬 서비스 연결, 상암 사건 상세를 실제로 엽니다.

```powershell
npm --prefix nicegui_dashboard/tests install
npm --prefix nicegui_dashboard/tests run smoke -- http://127.0.0.1:8092
```
